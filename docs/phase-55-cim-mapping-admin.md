# Phase 55 — CIM export mapping: admin editor + coverage fill

**Requested 2026-09-13** ("we've added many feature classes/attributes; check the CIM/XML export engine, especially mapping, and make it available in the admin UI"). Two audits (see below) confirmed the engine is healthy and fully metadata-driven — the problem is (a) mapping is **SQL/seed-only**, and (b) ~25 recently-added classes are **unmapped and silently dropped** from CIM export.

## What the engine does (audit, unchanged by this phase)

CDPSM / CIM16 (IEC 61968-13), `api/internal/export/cim.go` + `topology.go`/`electrical.go`/`phasing.go`/`containment.go`, orchestrated by `runner.go:134-218` (`runExport`, materialized under one REPEATABLE READ snapshot). Every feature class is resolved through three `metadata` tables (migration `0034`, phase transform added by `0035`):

- **`cim_profiles`** — one row per export target (CDPSM_CIM16 is the seeded `is_default`): `cim_namespace`, `profile_uri`, `model_authority`, `coordinate_crs`, `unmapped_attr_policy` (`drop`|`carry`; `carry` unimplemented), `is_default`.
- **`cim_class_mappings`** — `(feature_class_id, subtype_id?)` → `cim_class` + `cim_kind` ∈ {`conducting_edge`, `conducting_junction`, `container`, `asset`, `protection`, `skip`}. UNIQUE(feature_class_id, subtype_id); NULL subtype = class default, non-NULL = subtype override (`ClassFor` lets the override win).
- **`cim_attribute_mappings`** — `field_id` → `cim_attribute` (dotted `Class.attr`) + `transform` ∈ {`direct`, `scale`, `domain_map`, `boolean`, `from_geometry`, `material_spec`, `phase`} + `scale_factor`, `unit`, `value_map` (jsonb). UNIQUE(field_id, cim_attribute).

Loaded read-only by `metadata.LoadCIMMapping` (`api/internal/metadata/cim.go:100`), which JOINs codes over the wire (feature_class_code / integer subtype_code / field_name). **A class with no `cim_class_mappings` row → `ClassFor` returns ok=false → `cim.go:162-165` skips it silently.**

Mapping content today lives across five seeds: `cim_mapping_example.sql`, `mv_cim_mapping_example.sql`, `mv_lv_switch_parity.sql:182-196`, `mv_recloser_example.sql:264-278`, `mv_conductor_specs.sql:118-127`.

## The coverage gap (silently dropped from export today)

**Electrical, to be MAPPED (Slice 3):** POWER_XFMR, EARTHING_XFMR (→ PowerTransformer), GENERATOR (→ SynchronousMachine/GeneratingUnit; + `functional_role`), EV_CHARGING_STATION (→ EnergyConsumer), MV_EARTH_SWITCH (→ GroundDisconnector/Disconnector), MV_CABLE_JOINT/LV_CABLE_JOINT (→ Junction), RMU/MV_METERING_CUBICLE/MV_SWITCHGEAR_PANEL/MV_SWITCHBOARD/SUBSTATION_PANEL (→ EquipmentContainer/Bay), TOWER (→ asset like Pole).

**To be explicitly SKIPPED (`cim_kind='skip'`, so intentionally excluded not accidentally dropped):** EV_CHARGER, EV_CONNECTOR, STATION_BATTERY, BATTERY_CHARGER, CONTROL_IED, ANNUNCIATOR, CABLE_TRENCH/CABLE_DUCT/CABLE_CHAMBER/DUCT_WAY, CONTROL_BUILDING. (Decision 2026-09-13: "electrical core + explicit skips".)

**Attribute gaps** on already-mapped classes: `functional_role`, arc-flash geometry fields — map where a CIM analog exists, otherwise leave (documented).

## Slice plan (decision 2026-09-13: "editor first, then map")

- **S1 — Admin mapping editor.** Read+write admin CRUD for the three tables, no migration / no new permission / no new router mount (inherits `/admin` `metadata:read`/`metadata:write`). Go: routes + handler thunks + DTOs + list/create/update/delete + validation (enum whitelists mirroring the 0034/0035 CHECKs). Reuse `metadata.LoadCIMMapping` for reads; add code→id resolvers (copy `resolveDomainCodes`/`resolveMaterialSpecCode`). Web: `use-admin.ts` types + hook, `admin-cim-mappings.tsx` page (Domains-pattern flat page), route in `app.tsx`, sidebar entry in `app-sidebar.tsx`. Template map: Domains end-to-end.
- **S2 — Warn-on-unmapped safety net. BUILT static 2026-09-14** (go + npm build owed [[bash-tool-blocked]]; nothing committed). Two surfaces:
  - *Editor coverage view.* New read-only `GET /admin/cim-coverage` (`listCimCoverage` in `admin/cim.go`, DTO `cimCoverageResponse` code/name/geometry_type/network_role, handler + route + doc line in `handler.go`) = every `metadata.feature_classes` row with NO `cim_class_mappings` row of any kind (a `NOT EXISTS` anti-join; a class with even a `skip` row is "decided" and omitted). Frontend: `AdminCimCoverage` + `useAdminCimCoverage` in `use-admin.ts`; an amber "Unmapped classes" Card at the top of `admin-cim-mappings.tsx` listing each dropped class with geometry/network-role hints and a canWrite "Map…" button that opens the class-mapping dialog **prefilled** with that class (new `prefill` prop on `ClassMappingDialog`); class-mapping create/delete now also invalidate `["admin","cim-coverage"]` so the list stays live.
  - *Export-side log.* The equipment pass in `export/cim.go` now tallies drops (`cimWriter.unmapped` map, incremented only on the `!ok` branch — `skip` rows are deliberate, not counted), surfaced via `topoStats.Unmapped` (topology.go) and logged by `runExport` (runner.go) as a `CIM WARNING unmapped classes dropped from output: CODE=count …` line beside the existing topology-stats line (`formatUnmapped` helper, code-sorted).
- **S3 — Fill the gap. BUILT static 2026-09-14** (apply owed [[bash-tool-blocked]]; nothing committed). New seed `seed/cim_mapping_coverage.sql` (task `seed-cim-mapping-coverage`), same idiom as `cim_mapping_example.sql` (idempotent default profile; class-default rows via `NOT EXISTS`; attribute rows via `ON CONFLICT`). Authors:
  - *Mapped electrical core* (class-default rows): POWER_XFMR & EARTHING_XFMR → PowerTransformer, GENERATOR → SynchronousMachine, EV_CHARGING_STATION → EnergyConsumer, MV_EARTH_SWITCH → GroundDisconnector (all `conducting_junction`); MV_CABLE_JOINT & LV_CABLE_JOINT → Junction (`conducting_junction`); RMU/MV_METERING_CUBICLE/MV_SWITCHGEAR_PANEL/MV_SWITCHBOARD/SUBSTATION_PANEL → EquipmentContainer (`container`); TOWER → Tower (`asset`).
  - *Explicit skips* (`cim_kind='skip'`, `cim_class='(not exported)'` sentinel — required NOT NULL but decorative for a skip): EV_CHARGER, EV_CONNECTOR, STATION_BATTERY, BATTERY_CHARGER, CONTROL_IED, ANNUNCIATOR, CABLE_TRENCH, CABLE_DUCT, CABLE_CHAMBER, DUCT_WAY, CONTROL_BUILDING.
  - *Attribute mappings* (conservative, mirror established sibling patterns): POWER_XFMR & EARTHING_XFMR `primary_voltage` → BaseVoltage.nominalVoltage (`domain_map`, all four VOLTAGE_CLASS values `{"11KV":11000,"33KV":33000,"66KV":66000,"132KV":132000}`, unit V); MV_EARTH_SWITCH `device_state` → Switch.normalOpen (`boolean`, GroundDisconnector is a Switch subclass); POWER_XFMR `rated_mva` → PowerTransformerEnd.ratedS (`scale` **1000000.0** — nameplate is MVA→VA, *not* the 1000.0 the DIST_XFMR kVA seed used). EARTHING_XFMR carries no rating field, so it gets voltage only.

- **S4 — Real-sample CIM/XML preview per class. BUILT static 2026-09-14** (go + npm build owed [[bash-tool-blocked]]; nothing committed). Decision (AskUserQuestion): a **real-sample** preview (run one actual feature through the real encoder), not a synthesized skeleton — so it's byte-for-byte what export produces. Approach: run the *whole* `writeCIM` pipeline on a single-feature layer set (not the unexported per-feature emitter in isolation) so the output is a complete, self-consistent CIM document — header + scaffold + the feature's BaseVoltage + equipment element + synthesized Terminals/ConnectivityNodes, no dangling refs (the topology pass builds valid isolated terminals from metadata even with zero connectivity rows).
  - *Backend.* New `export.PreviewFeature(ctx, db, classCode, profileCode) (FeaturePreview, error)` in `api/internal/export/preview.go`: one REPEATABLE READ read-only snapshot (mirrors `runExport`), `gatherLayers([classCode])` → keep the first feature only → `LoadCIMMapping`/`loadConnectivity`/`loadContainment`/`loadMaterialSpecs` scoped to it → `writeCIM` into a `bytes.Buffer`. A geometry-less class (gatherLayers 400) or one with no rows is **not an error** — returns `Sampled=false` + a `Note` (matches reality: the CIM export never emits geometry-less classes). New admin `GET /admin/cim-preview/{code}` (`?profile=` optional) — `getCimPreviewHandler` + `cimPreviewResponse` DTO (class_code/feature_id/xml/sampled/note); admin now imports the export package (no cycle — export doesn't import admin).
  - *Frontend.* `AdminCimPreview` + `useAdminCimPreview(classCode)` (on-demand, `enabled: !!classCode`, `staleTime: 0` since it reflects live feature data) in `use-admin.ts`; `PreviewDialog` (plain `Dialog`, not `FormDialog`, so Esc/outside-click close) shows the XML in a scrollable `<pre>` with a Copy button and the sampled feature id, and renders the `note` when `sampled` is false; a `FileCode2` "CIM/XML preview" icon-button on each **Class mappings** row (read-only, shows regardless of `metadata:write` — new optional `onPreview` on `RowShell`).

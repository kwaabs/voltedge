Where is each asset
in its life?

Every feature carries a lifecycle axis — planned, in service, derated, retired, removed. It decides what the live network is (planned and retired assets don't conduct), how the map reads, and what needs replacing. This edition is a working one: drive the state machine, break and heal a feeder by retiring a span, and age an asset against its expected life.

Use As in the top bar. Pat is a planner (features:write) — changes an asset's lifecycle. Val (features:read) views the report but can't change a thing. Ada is an admin (metadata:write) — hers is the expected-life catalog. Controls lock to what the persona may do.

Don't confuse the three axes

VoltEdge has three "status"-shaped questions, and lifecycle is only one of them. Editorial status = draft or published. Availability (class status) = is this class still offered. Lifecycle lifecycle_status = where this asset is in its physical life. A feature can be a published draft of a PLANNED asset of a still-offered class — three independent answers.

Remaining useful life

Only in-service assets age. Planned ones aren't built; retired/removed ones are already handled — all excluded, the same operational set the network gate uses. A subtype_code of NULL is the class default; set it to override one subtype (a wood pole ≠ a steel tower).

someone's land.

Easements, parcels, corridors and vegetation are feature classes — and VoltEdge then derives the relationships from the shapes: what sits inside an easement, what land covers a pole, what trees breach clearance on a feeder. This guide runs the real geometry in your browser (point-in-polygon, geodesic distance, the per-voltage clearance rule, the date queries) on a small estate you can poke.

01

The four land classes

Polygons that are context, not network nodes.

All four are network_role 'none' polygons — land/legal/environmental context, not nodes power flows through. They seed draft; publish them from /admin after task compile. The bold fields drive the due tracking in Chapter 4.

LAND_PARCEL

A cadastral land unit — the land an easement burdens.

parcel_ref · owner_name · land_use · area_sqm

EASEMENT

The legal right to keep the network's assets on the land.

easement_ref · easement_type · status · grantor · granted_date · expiry_date

UTILITY_CORRIDOR

The managed strip (right-of-way) the network runs through.

corridor_type · corridor_ref · width_m · managed

VEGETATION_ZONE

A patch of vegetation, for clearance / trim analysis.

veg_type · species · height_m · condition · last_trimmed · trim_cycle_months

Why geometry-derived VoltEdge's connectivity and relationships are authored — you wire them. The spatial engine instead reads the shapes across the compiled gis.* tables, so a pole never has to be linked to an easement for "is it on one?" to have an answer.
02

The spatial engine

Pick a reference and a mode; the geometry answers.

GET /spatial/related returns the features spatially related to one reference, in four modes. Pick a reference feature and a mode below — the map highlights the matches and the real predicate runs (ray-cast point-in-polygon, segment distance).

Class codes resolve to their physical table through metadata (a whitelist); feature ids are bound; the reference geometry is fetched by a subquery. A table name is never taken from the request, and the geometry never round-trips through the app.

Due tracking

The proactive side: easements expiring and trims coming due. Slide today forward and watch the badges flip — the same arithmetic ExpiringEasements and VegetationTrimDue run (expiry_date − today; last_trimmed + trim_cycle_months).

Honest limits The land classes seed draft (compile + publish before use). The per-voltage clearance values are illustrative. No standalone due-report panel or breach map overlay yet (the per-feature badge ships; the lists are reachable via API/tools). A whole-network spatial scan isn't offered — scope to one reference / conductor / circuit. Land records are not territory-scoped.
